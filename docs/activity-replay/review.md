# Bounded historical activity threshold replay

Independent branch from main 24de1c2. A monitor draft can compare ERROR_RATE or fixed LOW_VOLUME against retained raw activity on one explicit authorized channel. POST /monitors/_replay requires Manage Monitoring and never saves a monitor, changes triggers/incidents, or queues notifications. Error-rate comparison shares live evaluator math; fixed low-volume uses the existing strict count comparison. Threshold comparisons assume runtime eligibility; historical deployment, schedules, dependencies, opening/recovery progress and delivery are explicitly unknown.

Bounds: past range <=24h, step 60..3600 seconds (default300), <=1000 sampled evaluation instants, condition window 1..86400 seconds, gap tolerance 1..1200 seconds (default120), <=10000 raw samples including lookback. Query lookback is condition window plus tolerance, so the total raw query can cover up to 48h20m. MyBatis RowBounds caps materialized rows at10001; this is not a vendor-specific SQL LIMIT or a database execution-time guarantee. Above cap, replay rejects the request rather than calculating from a truncated series. Existing channel/time indexes and existing five-vendor mapped query are reused; no migration.

Each instant requires a baseline at/before window start within tolerance, no larger interior gap, and a latest sample within tolerance. Window sums include both endpoints, matching the live aggregate query. Empty retention, stale tail and missing coverage remain unknown; hourly rollups never substitute. Runs group adjacent equal results only at the requested sampled instants. They do not establish continuous breach intervals or historical engine timing, latency, incidents or notification counts. Available raw extent/count and per-point captured comparison evidence are returned and displayed.
