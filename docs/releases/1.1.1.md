# OIE Sentinel 1.1.1

Maintenance release for **OIE 4.6.0**, fixing monitor creation, alert delivery, clustered monitoring, and database installation failures.

## Fixed

- Creating a monitor without a suppression parent now succeeds on PostgreSQL. Optional numeric and timestamp fields also bind correctly across all five supported database vendors.
- Alert and trigger updates commit together. Failed writes and concurrent acknowledgement/resolution no longer leave incidents stranded, overwrite the first acknowledgement, or reset a newer incident.
- Pending initial and recovery notifications survive a full dispatch queue, restart, and partial delivery to multiple actions. Recovery follows the initial notification when both are applicable. Transport waits are bounded, and a shutdown/restart race that could duplicate notifications is fixed.
- Maintenance windows, alerting schedules, and parent-monitor suppression are checked again before sending. Persistent problems can notify when suppression ends; queued repeats and escalations respect current policy.
- Cluster leaders now evaluate connector observations from every live node that deploys the connector, including paused and follower-only deployments. Missing observations remain unknown, and stale observations are rejected when deployment identity changes.
- Leadership epochs fence background writes and notification completion. Expired leaders roll back protected writes, and collector counter baselines reset on leadership changes.
- Incomplete scope inventories no longer falsely resolve existing incidents. Confirmed departures still close the affected alerts.
- Oracle fresh installation and PostgreSQL uninstall/reinstall no longer fail on invalid DDL or conflicting index names. Repeated archival preserves retained data across supported vendors.
- Community Store catalog metadata preserves the supported maximum engine version, matching the plugin's exact OIE 4.6.0 compatibility.

## Upgrading

**For a cluster, stop Sentinel on every node before starting the updated plugin on any node. All nodes must run the updated version before monitoring resumes.**

Install 1.1.1 over the existing plugin; do not uninstall as an upgrade step. Restart the engine after installation. The schema upgrades automatically from version 6 in Sentinel 1.1.0 to version 12, preserving monitors, actions, schedules, and alert history.

Existing connector observations without deployment identity remain unknown until a current observation arrives. Previously damaged partial schemas left by an older failed uninstall are not automatically repaired.

## Delivery and validation notes

A crash after an external send but before its dispatch-log commit can cause a duplicate on retry; delivery is not exactly once. Connector deployment identity uses the engine's timestamps, whose clock-adjustment limits are described in the [architecture documentation](../ARCHITECTURE.md).

The fixes passed 868 regression tests, real database checks on Derby, PostgreSQL, MySQL, Oracle, and SQL Server, and additional PostgreSQL fencing/concurrency tests. The release workflow builds against OIE 4.6.0 and provides the installable ZIP, SHA-256 checksum, and signed build provenance.
