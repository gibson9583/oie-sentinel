# OIE Sentinel 1.2.1

Maintenance release for **OIE 4.6.0** that improves activity collection and monitor evaluation under database contention and fixes MySQL timestamp reads. The supported engine range remains exactly 4.6.0.

## Changes

- Activity snapshots and collector batches retry once after a recognized Derby, MySQL, or SQL Server deadlock and successful transaction cleanup. Retries preserve consistent snapshots, original sample values, and the original leadership fence.
- MySQL timestamp reads now work with the engine's Connector/J defaults across monitor, action, alert, activity, schedule, and lease queries. No JDBC URL workaround is required.
- Timeouts, cancellation, connection failures, uncertain cleanup, and exhausted retries still propagate without further replay. PostgreSQL, Oracle, and other read transactions retain their existing retry behavior.

## Upgrading

Install 1.2.1 over the existing extension and restart the engine. **Do not uninstall as an upgrade step:** explicit uninstall deletes Sentinel's live configuration and history tables.

For a cluster, stop Sentinel on every node, install the same archive everywhere, then restart. A rolling mixed-version upgrade is not supported. Retain a consistent database backup, matching encryption material, and the previous plugin archive before upgrading.

An upgrade from 1.2.0 keeps schema version 13 and the existing configuration and data formats. Check for one active monitoring leader, fresh collector samples, and expected monitor results after restart. Upgrades from 1.1.2 or earlier must also follow the [1.2.0 migration and encrypted-webhook guidance](1.2.0.md#upgrading).

For rollback, follow the [coordinated backup and restore procedure](1.2.0.md#rollback). Uninstall is not a rollback step.

## Validation and known limitations

The fixes passed 1,722 Java tests and 62 webadmin tests. Database validation includes real Derby, MySQL, PostgreSQL, and SQL Server runs, plus native Derby JDBC batch-deadlock and lease-takeover checks with both engine connection pools. The MySQL checks use the shipped Connector/J 8.4.0 without a timestamp compatibility flag. Oracle was not tested live for this patch.

- [Issue #70](https://github.com/gibson9583/oie-sentinel/issues/70) remains open: near the 500-incident dashboard cap, concurrent resolutions can temporarily show a green channel badge while an incident remains open. Incident records and notification delivery are unaffected.
- Notification delivery remains at least once; a crash after sending but before recording completion can cause a duplicate.
